> 本文基于对仓库源码的实际核实（不是照抄 README），记录本机已跑通的配置与后续上服务器的步骤。
>
> 📓 整个项目的实施过程、企微后台配置全流程与踩坑记录，见 [`实施记录.md`](实施记录.md)。

## 一、系统实际构成

| 组件 | 说明 |
|---|---|
| 后端 | Spring Boot 2.7.3 / JDK 17，入口 `cn.iyque.IyQueApplication`，端口 **8085** |
| 数据库 | MySQL 8。**建表 SQL 在 `configFile/scrm_push.zip` 里**，52 张表，已解压到 `deploy/sql/scrm_push.sql` |
| Redis | 必需。被 `RateLimitAspect`（登录限流：5 次失败锁 5 分钟）使用，`database: 1` |
| Milvus | 只有用 AI 知识库时才懒加载（`MilvusVectorStore`），不用 AI 可以不装 |
| PC 后台 | `frontEnd/pc`，Vue3+Vite，dev 端口 2024，路由 base `/tools/` |
| 移动端 | `frontEnd/mobile`，员工端 / 投诉 H5 / 客户公海 H5，dev 端口 1026，路由 base `/openmobile/` |
| 登录账号 | `application.yml` 里的 `iyque.userName` / `iyque.pwd`，默认 `iyque` / `iyque.cn` |

注意：`spring.jpa.hibernate.ddl-auto: none`，**不会自动建表**，必须先导入 SQL。

## 二、本机启动（已跑通）

```bash
cd Iyque-SCRM
./deploy/start-local.sh     # 启动全部
./deploy/stop-local.sh      # 停止全部（保留数据）
```

访问：

- PC 后台 <http://localhost:2024/tools/> — 账号 `iyque` / 密码 `iyque.cn`
- 移动端 <http://localhost:1026/openmobile/>
- 后端 API <http://localhost:8085>

数据库：`127.0.0.1:10179`，库 `scrm_ky`，`root/root`（跑在 docker 里，数据在 volume `deploy_iyque-mysql-data`）。

### 踩过的两个坑

1. **PC 前端依赖装不上**：`@vitejs/plugin-vue-jsx@3` 的 peer 要求 vite 4/5，但项目用 vite 6，`npm install` 和 `npm ci` 都会 ERESOLVE 失败。该插件在 `vite.config.ts` 里根本没被引用，是上游遗留的无用 devDep。解法：
   ```bash
   cd frontEnd/pc && npm install --legacy-peer-deps
   ```
2. **移动端 dev 启动报 esbuild 错**：`src/components/Upload.vue` 从 `@/api/common` 导入了不存在的 `getVideoPic`。该符号全项目仅出现在那一行（死导入），而 `Upload.vue` 被「客户投诉」页面实际使用。已改为：
   ```js
   import { getCosConfig, upload } from '@/api/common'
   ```

## 三、接通企业微信（备案是硬前提）

> **2026-08-31 实测结论，与官方文档不符，务必先看这条：**
>
> 企业微信**对「接收消息服务器URL」（回调）同样强制校验域名备案主体**，报错
> 「域名主体校验未通过，需配置备案主体与当前企业主体相同或有关联关系的域名」。
>
> 官方文档 <https://developer.work.weixin.qq.com/document/path/90930> 通篇没提备案，
> 只写了 echostr 验签流程，但实际后台就是拦。所以**「只做活码/自动打标签/自动备注
> 就不用备案」这个结论是错的**。
>
> 连锁影响：「企业可信IP」的前置条件是「设置可信域名 **或** 设置接收消息服务器URL」，
> 两条路现在都要备案，等于**没有备案域名就完全无法对接企微 API**。
>
> 且备案主体必须与企微认证主体相同或有关联关系。ICP 备案又要求大陆境内服务器+接入商，
> 所以香港/海外服务器方案在企微场景下走不通。



企微自建应用要求可信域名 / 可信 IP / 回调 URL 均为公网可达的 HTTPS 地址，**所以本机部署只能看界面、点不通企微**。真正要管理企微，需要：

- 一台公网 Linux 服务器（建议 4C8G 起，SCRM + MySQL + Redis；开 AI 再 +2G 给 Milvus）
- 一个已备案的域名 + SSL 证书（企微可信域名需要上传校验文件验证域名归属）

### 企微后台要做的事（管理后台 work.weixin.qq.com）

1. **应用管理 → 自建应用 → 创建应用**，记下 `AgentId` 和 `Secret`
2. **我的企业 → 企业信息**，记下 `企业ID (CorpId)`
3. 自建应用 → **开发者接口 → 接收消息 → 设置API接收**
   - URL：`https://你的域名/iyque/iycallback/handle`
   - 自己生成 `Token` 和 `EncodingAESKey`（保存下来）
   - 对应后端 `IYcallbackController#handle`（GET 验签 / POST 收事件）
4. 自建应用 → **企业可信IP**：填服务器公网 IP
5. 自建应用 → **网页授权及JS-SDK / 可信域名**：填你的域名，按提示下载校验文件放到网站根目录
6. **客户与上下游 → 客户联系 → 客户联系API → 可调用接口的应用**：把上面那个自建应用加进去
   （源码 `WxCpServiceFactory` 只用一个 secret 打所有接口 —— `wxCpConfig.setCorpSecret(config.getAgentSecert())`，所以这个自建应用的 Secret 必须同时具备客户联系权限，这一步不能漏）
7. 通讯录：自建应用默认可读「可见范围」内的通讯录，把要管理的员工加进可见范围

### 系统里填哪儿

登录 PC 后台 → **配置**（`frontEnd/pc/src/views/config`）→ 填写：

| 字段 | 来源 |
|---|---|
| corpId | 我的企业 → 企业ID |
| agentId | 自建应用 → AgentId |
| agentSecert | 自建应用 → Secret |
| token | 接收消息设置里你生成的 Token |
| encodingAESKey | 接收消息设置里你生成的 EncodingAESKey |

存到 `iyque_config` 表（初始为空表）。填完先在企微那边点「保存」验证回调 URL 能通过。

会话存档相关的 `msgAuditSecret` / `msgAuditPriKey` / `msgAuditLibPath` 属于 AI 会话功能，需要企微「会话内容存档」付费服务 + Linux 的 `libWeWorkFinanceSdk` 动态库，macOS 上跑不了。

## 四、上服务器时要改的配置

### 后端 `src/main/resources/application.yml`

```yaml
iyque:
  userName: 改掉        # 默认 iyque
  pwd: 改成强密码        # 默认 iyque.cn，别用默认值上公网
  fileViewUrl: https://你的域名/iyque/file/fileView/
  complaintUrl: https://你的域名/openmobile/customerComplaint
  customerSeasUrl: https://你的域名/openmobile/customerSeas
  h5MarketUrl: https://你的域名/openmobile/H5Marketing?id={0}
spring:
  datasource:
    url: jdbc:mysql://内网地址:3306/scrm_ky?...
    username: 专用账号   # 别用 root
    password: 强密码
  jpa:
    show-sql: false      # 默认 true，生产会刷爆日志
```

`ai.models.configs.glm-4.api-key` 和 `ai.vector.configs.embedding-3.api-key` 里那个 key 是官方仓库里带的公共 demo key，要用 AI 功能必须换成自己的智谱 key。不用 AI 就不用管。

### 前端 `sys.config.ts` / `sys.config.js`

两个文件里的 `production` 段都写死了 `https://iyque.cn`，必须改成你的域名，否则打包出来的前端会去请求源雀官网：

```ts
production: {
  DOMAIN: 'https://你的域名',
  BASE_URL: '/tools/',        // mobile 是 '/openmobile/'
  BASE_API: 'https://你的域名/iyque',
},
```

改完分别 `npm run build`，产物 `dist/` 传到服务器：
- pc 的 dist → `/usr/local/nginx/html/prod/tools`
- mobile 的 dist → `/usr/local/nginx/html/prod/openmobile`

### nginx

参考 `configFile/nginx.conf`，关键是这三段（把 `iyque.cn` 换成你的域名、证书换成你的）：

```nginx
location ^~ /iyque/ { proxy_pass http://127.0.0.1:8085/; }   # 注意末尾斜杠，会剥掉 /iyque 前缀
location /tools      { root /usr/local/nginx/html/prod; try_files $uri $uri/ /tools/index.html; }
location /openmobile { alias /usr/local/nginx/html/prod/openmobile; try_files $uri $uri/ /openmobile/index.html; }
```

所以企微回调 URL 是 `https://域名/iyque/iycallback/handle` → 实际打到 `127.0.0.1:8085/iycallback/handle`。

## 五、上服务器前的安全清单

- [ ] **改掉 `JwtUtils.java:13` 的 `SECRET_KEY`** —— 上游硬编码为 `iYqueSecretKeyForJwtTokenGenerationAndValidation` 并公开在 GitHub 上，不改的话任何人都能给你的部署伪造管理员 token。这条比改密码更要紧

## 七、移动端本地调试的 token 坑

本机用 Chrome 打开 <http://localhost:1026/openmobile/> 会弹「登录状态已过期」。

原因不是你没登录，而是 `frontEnd/mobile/src/config.js` 最后有个开发后门：

```js
process.env.NODE_ENV === 'development' && window.sysConfig.TOKEN && (sessionStorage.token = window.sysConfig.TOKEN)
```

它把上面硬编码的 JWT 塞进 sessionStorage，好让开发者跳过企微授权。但上游提交进仓库的那串 token 签发于 2026-03-03、7 天后就过期了，后端 `JwtInterceptor` 判定失效返回 401，`src/utils/request.js:39` 的拦截器就弹了这个框。

解法（token 只有 7 天有效期，过期就再跑一次）：

```bash
./deploy/refresh-mobile-dev-token.sh   # 需要后端 8085 在跑
```

注意：移动端本来就是要**在企业微信客户端里**打开的（员工侧边栏 / 投诉 H5 / 客户公海待办），正式登录走企微 OAuth 换 authCode。浏览器直开只是本地看界面用。

## 八、分支策略与合并上游更新

```
remote  origin    → github.com/dev-longshun/QiWei-SCRM   （你自己的仓库，公开）
remote  upstream  → github.com/IYque/Iyque-SCRM          （源雀官方，只读取不推送）

分支    main      ← 你的分支，所有改动提交在这里；也是 GitHub 上的默认分支
分支    master    ← 上游基线，只跟 upstream/master 同步，永远不在上面改东西
```

上游（源雀官方）发新版本时：

```bash
# 1. 看看他们改了什么
git fetch upstream
git log --oneline master..upstream/master

# 2. 更新上游基线分支
git checkout master
git merge --ff-only upstream/master
git push origin master

# 3. 合并进自己的分支
git checkout main
git merge master
# 解决冲突（见下表）后
git push origin main
```

合并时最容易冲突的是这几个文件（因为我们改过）：

| 文件 | 冲突时怎么处理 |
|---|---|
| `frontEnd/mobile/src/config.js` | 上游可能又换了硬编码 token。保留我们的（或合并后重跑 `deploy/refresh-mobile-dev-token.sh`） |
| `frontEnd/mobile/src/components/Upload.vue` | 如果上游自己修了 `getVideoPic`，用上游的 |
| `.gitignore` | 两边都留 |
| `frontEnd/pc/package-lock.json` | 直接用上游的，然后重跑 `npm install --legacy-peer-deps` |
| `src/main/resources/application.yml` | 上线后这里会有你的数据库密码等，务必用自己的 |
| `configFile/scrm_push.zip` | **重点**：上游更新这个 zip 说明表结构变了。合并后要对比新旧 SQL，手工写 ALTER 语句升级已有数据库，不能直接重导（会清空数据） |

上游发版节奏参考：tag 从 `V20250304` 到 `V2.1`，大致每 1–2 个月一次。

合并前先备份数据库：

```bash
docker exec iyque-mysql mysqldump -uroot -proot scrm_ky > ~/scrm_ky_$(date +%Y%m%d).sql
```

| 服务器 | shan-dmit-hk `103.117.101.244`（香港 DMIT，4C/7.8G） |

| 移动端/H5 | https://qiwei.longjinapi.com/openmobile/ |
| 企微回调 URL | `https://qiwei.longjinapi.com/iyque/iycallback/handle` |
| 证书 | Let's Encrypt，至 2026-11-29，certbot 自动续期 + deploy hook 重载 nginx |

### 选型依据

实测各机到 `qyapi.weixin.qq.com` 的单次请求耗时：香港 DMIT **57ms**、AWS 香港 50ms、美国 DMIT **490ms**。
回调处理是同步的（`IYqueCustomerInfoServiceImpl:72` 无 `@Async`），内部串行 4 次企微调用，
美国机 4×490ms≈2s 必然超出企微 1 秒窗口，故排除。lisa-hk 仅剩 773M 内存、ouyang 的 443 被
sing-box 占用，均不可用。

### 目录布局

```
/root/qiwei-scrm/
  docker-compose.yml   mysql(qiwei-mysql) + redis(qiwei-redis) + backend(qiwei-backend)
  .env                 全部密钥，chmod 600，不进 git
  config/application.yml  生产覆盖配置，经 SPRING_CONFIG_ADDITIONAL_LOCATION 挂载
  app/app.jar          后端 fat jar
  sql/scrm_push.sql    首次启动自动导入
  upload/              素材上传
  data/                mysql + redis 持久化
  backups/             每日备份，保留 7 天（cron 04:17）
/var/www/qiwei/tools|openmobile   前端静态产物（nginx 跑 www-data，读不了 /root）
/etc/nginx/sites-enabled/qiwei-scrm
```

### 端口

宿主机 8085 已被其他业务占用，后端改用 **18085**；MySQL 13306、Redis 16379。
三个端口**全部只绑 127.0.0.1**，对外只经 nginx 443。

### 上线时做的加固

| 项 | 处理 |
|---|---|
| `JwtUtils` 硬编码密钥 | 改为读 `IYQUE_JWT_SECRET` 环境变量，生产用 64 字节随机值。已实测：用上游公开密钥伪造的 token 返回 401 |
| 默认账号 `iyque`/`iyque.cn` | 换成自定义账号 + 20 位随机密码，实测旧账号被拒 |
| MySQL root | 应用连接改用独立账号 `iyque`，不使用 root |
| `show-sql: true` | 关闭，同时把 mybatis-plus 日志改为 NoLoggingImpl |
| 容器资源 | backend `-Xmx1g`/mem_limit 1.5G、mysql 1.2G、redis 200M（本机已有 24 个容器） |

实际占用：backend 398M / mysql 204M / redis 6M，合计约 610M。
