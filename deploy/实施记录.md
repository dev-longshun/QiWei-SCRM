## 一、最重要的一条结论（如果只看一句话）

> **想用企业微信的 API 自建 SCRM，ICP 备案是绕不过去的硬前提，且备案主体必须与企微认证主体一致。**
> **没有备案域名 = 一个企微接口都调不了。**

这条在企微官方文档里**没有明确写**，我们是撞上去才知道的。详见第三节。

## 二、企业微信管理后台配置全流程

### 2.1 前置条件（不满足就别往下做）

| 条件 | 说明 | 我们的情况 |
|---|---|---|
| 企业已完成**企业认证** | 不是"验证"。认证 ¥300/年，需年审，审核 10-15 工作日 | ✅ 已完成 |
| 已备案域名 | 备案主体须 = 企微认证主体 | ❌ 卡在这 |
| 大陆服务器 | ICP 备案要求境内服务器+境内接入商 | ✅ 已买 |
| 外部联系人额度 | 免费 2000 个，超出需付费 | 待评估 |

⚠️ **「验证」和「认证」是两回事**：验证免费（法人扫脸/对公打款），认证要 ¥300/年。
**客户联系 API 需要的是「认证」**。未认证的企业只能添加 100 个客户，SCRM 基本没法用。

### 2.2 配置顺序（顺序错了会白折腾）

```
① 创建自建应用            → 拿 AgentId、Secret
② 我的企业 → 企业信息      → 拿 CorpId
③ 源雀后台填配置并保存     → 含自己生成的 Token / AESKey
④ 企微：设置接收消息服务器URL → 企微此时会来打你的回调做验签
⑤ 企微：企业可信IP          → 前置条件是 ④ 或「可信域名」
⑥ 客户联系 → 可调用接口的应用 → 把自建应用加进去
```

**③ 必须在 ④ 之前。** 企微点保存的瞬间就发验证请求，后端要能从数据库读到
Token/AESKey 才算得出签名。反了必失败，而且报错信息会让你误判成别的问题。

### 2.3 五个字段分别从哪来

| 源雀里的字段 | 来源 | 注意 |
|---|---|---|
| 企业ID (CorpId) | 我的企业 → 企业信息 → **拉到最底部** | 形如 `ww1a2b3c4d5e6f7g8` |
| 应用ID (AgentId) | 自建应用详情页 | 一串数字，如 `1000002` |
| 应用Secret | 自建应用详情页点「查看」 | **不在网页显示**，企微推送到你的企业微信 App |
| Token | **自己生成** | 源雀页面有「随机获取」按钮 |
| AESKey | **自己生成** | 43 位 |

⚠️ Token 和 AESKey 不要去企微找，找不到 —— 是你自己生成后**同时填到两边**，企微拿它验签。

### 2.4 回调 URL 怎么拼

```
https://<你的域名>/iyque/iycallback/handle?corpId=<你的企业ID>
```

- `/iyque/` 是 nginx 反代前缀，配置里 `proxy_pass http://127.0.0.1:18085/;`
  **末尾那个斜杠**会剥掉 `/iyque`，最终打到后端的是 `/iycallback/handle`
- 对应源码 `IYcallbackController`（`@RequestMapping("/iycallback")` + `@GetMapping("/handle")`）
- 源雀页面上那个只读输入框里的 `{企业id}` 是**字面占位符，不会自动替换**，粘贴时要手动换掉
- `?corpId=` 这段后端其实不读（它直接查数据库配置），带不带都行

### 2.5 踩坑记录

#### 坑 1：可信域名报「不能包含协议头」

填了 `https://qiwei.longjinapi.com`，报红。

**原因**：可信域名只填域名本体，不带 `https://`。正确写法 `qiwei.longjinapi.com`。

#### 坑 2：可信域名报「域名主体校验未通过」

> 需配置备案主体与当前企业主体相同或有关联关系的域名

**原因**：域名没备案，或备案主体与企微认证主体不一致。这是**硬性要求**，不是提示。

**注意**：网上有大量案例反映，即使两边主体**完全一致**仍会被误判，
需要用**管理员或分管账号**联系企微客服提交表单人工审核（普通账号只会收到机器人回复）。

#### 坑 3：可信IP 填不了，提示要先设别的

> 配置企业可信IP前，请先 设置可信域名 **或** 设置接收消息服务器URL

**关键是那个「或」** —— 两个满足一个即可，不必两个都配。

#### 坑 4（最关键）：接收消息服务器URL 也查备案

我们原本判断：可信域名查备案，但**回调 URL 不查**（官方文档
<https://developer.work.weixin.qq.com/document/path/90930> 通篇只写 echostr 验签流程，
没有任何备案要求）。据此我们以为「只做活码 + 自动打标签 + 自动备注」可以不备案。

**实测结果：错的。** 在「接收消息服务器URL」填未备案域名，同样报
「域名主体校验未通过」。

于是形成死锁：

```
企业可信IP  ← 前置是「可信域名」或「接收消息URL」二选一
                    ↓                    ↓
                 查备案                查备案
```

**结论：没有备案域名，企微 API 一个都调不了。**

#### 坑 5：源雀页面上那句备案提示是它自己写的

源雀配置页回调地址下方有一行灰字：

> 回调是需要依托域名的,且域名备案主体需要与企微认证主体一致

一度以为是企微返回的错误。实际是硬编码在
`frontEnd/pc/src/views/config/agent.vue:27` 的一行静态 HTML，
任何人打开这页都会看到，与你的域名状态无关。

**教训**：分不清"页面静态文案"和"接口返回的错误"时，直接去源码里搜那句话。

### 2.6 一个容易漏的授权

源雀的 `WxCpServiceFactory` 用**同一个 secret 调所有接口**：

```java
wxCpConfig.setCorpSecret(config.getAgentSecert());
```

所以必须在 **客户与上下游 → 客户联系 → 客户联系API → 可调用接口的应用**
里把这个自建应用加进去，否则客户列表、活码、打标签全部 401。

## 三、ICP 备案（个体工商户 / 湖北）

### 3.1 主体链：四处必须完全一致

```
企微认证主体  =  云账号实名主体  =  域名实名持有者  =  ICP 备案主体
```

我们的主体：**武汉市东西湖区隆金网络科技工作室**（个体工商户）

⚠️ 一定要用**营业执照上的完整名称**。我们最初口头说的是"武汉隆金网络科技"，
实际执照全称多了「武汉市东西湖区」前缀和「工作室」后缀 —— 差一个字备案就会被打回。

### 3.2 香港/海外服务器备不了案

ICP 备案要求绑定**大陆境内服务器 IP + 境内接入商**，香港 IP 不被接受。
港澳台及海外不在备案体系内 —— **不是"不用备案"，是根本没法备案**。

这是我们废弃香港部署方案的直接原因。

### 3.3 域名注册商也有限制

境外注册商（GoDaddy / Namecheap / Cloudflare Registrar）注册的域名**无法备案**，
因为它们不向工信部报送域名注册人信息。

必须在境内有资质的注册商注册：腾讯云(DNSPod) / 阿里云(万网) / 华为云 / 西部数码 / 新网 等。

已在境外注册的域名要转入境内，且**新域名需注册满 60 天才能转出**。

### 3.4 域名后缀怎么选

| 后缀 | 能否备案 | 微信风控 | 建议 |
|---|---|---|---|
| `.cn` | ✅ | 友好 | ✅ 首选，通常比 .com 便宜 |
| `.com` | ✅ | 友好 | ✅ 次选 |
| `.top` `.xyz` `.icu` | ✅ 可备案 | ⚠️ **风控严，容易被拦** | ❌ 不建议 |

`.top`/`.xyz` 这类新后缀确实能备案，但**微信对它们采用更严格的风控**，容易触发域名拦截。
对 SCRM 是致命的 —— 投诉页、H5 营销页、客户公海都要在微信/企微里打开，被拦就全废。

为省几十块钱赌这个不划算。权威可备案后缀列表：<http://domain.miit.gov.cn/>

### 3.5 湖北管局规则

| 项 | 要求 |
|---|---|
| 主体负责人 | **必须是营业执照上的经营者本人**，不能代持挂靠 |
| 网站负责人 | 非法人需授权委托书（建议填本人省事） |
| 域名 | 有效期 > 30 天；**持有者名称须与主办单位一致** |
| 核验方式 | 人脸核验（云厂商 App，不用寄幕布） |
| 数量限制 | 自 2019-03-20 起，**一次只能备 1 个网站 1 个域名** |
| 审核时长 | **8–12 工作日** |
| 备案后 | 网站底部**必须挂 ICP 备案号**并链接工信部平台（管局抽查项） |

### 3.6 名称含「工作室」会触发加严

个体工商户 / 单位名称含 **商贸、百货、工作室、经营部、服务部** 等字样：

- 一次仅限提交 1 个域名
- 需**法人手持营业执照 + 手持身份证**拍照
- 部分地区要求**社保证明**

我们的主体名带「工作室」，正好命中。且该主体 2026-04-08 才注册，
若被要求以该主体缴纳的社保证明，大概率拿不出 —— 到时走云厂商备案客服沟通。

### 3.7 网站名称别踩雷

不要用：资讯、网站、网络、网址、平台、工作室、主页、论坛、社区。
（这跟单位名称是两回事，单位名叫什么由执照定，改不了。）

我们计划填：**隆金客户管理系统**

### 3.8 腾讯云个体工商户实名

没有对公账户也能做，走「**企业法人人脸识别认证**」：
只需填经营者姓名 + 身份证号，扫码刷脸，几分钟完成。二维码 1 小时有效。

⚠️ **必须先完成企业实名再买服务器和域名**。先用个人实名买了再改，备案时主体对不上很麻烦。

## 四、服务器与部署踩坑

### 4.1 选服务器的决定性指标：到企微 API 的延迟

源雀的企微回调处理是**同步**的 —— `IYqueCustomerInfoServiceImpl:72`
的 `addCustomerCallBackAction` 没有 `@Async`，内部串行调 4 次企微接口
（`getContactDetail` → 欢迎语 → `markTag` → `updateRemark`），
全部要挤进企微要求的 **1 秒**响应窗口。

实测各机到 `qyapi.weixin.qq.com` 的单次请求耗时：

| 机器 | 耗时 | 4 次串行 | 结论 |
|---|---|---|---|
| AWS 香港 | 50ms | ~200ms | 可用 |
| DMIT 香港 | 57ms | ~230ms | 可用 |
| **腾讯云上海（现用）** | **88ms** | ~350ms | ✅ 可用 |
| DMIT 美国 | **490ms** | **~2s** | ❌ 必超时 |

**选服务器前先测这个**，比看 CPU 内存重要得多。测法：

```bash
curl -o /dev/null -s -w "%{time_total}\n" https://qyapi.weixin.qq.com/cgi-bin/gettoken
```

> **值得做的改造**：给 `addCustomerCallBackAction` 加 `@Async`（项目里已有
> `AsyncConfig` 和现成线程池，同文件 536 行就是这么用的），改成立刻返回 `success`
> 再异步处理。好处：回调永不超时、企微不会因超时重推导致重复打标签、
> 换任何地域的机器都能跑。

### 4.2 前端产物写死了域名

`sys.config.ts` / `sys.config.js` 的 `production` 段写死了完整域名，
而运行时是拿 `window.location.origin` 去匹配 `DOMAIN` 决定用哪套配置。
用 IP 访问时匹配不到任何环境，`envs[undefined]` → 接口地址变 `undefined`，整站瘫。

**我们的改法**：让 `production` 成为兜底环境，`DOMAIN` 和 `BASE_API` 都在运行时按
`location.origin` 拼接。这样**同一份产物在 `http://IP` 和 `https://域名` 下都能跑，
备案通过后不用重新打包**。

⚠️ `BASE_API` 必须保持**绝对地址**（`origin + '/iyque'`），不能改成相对路径 ——
`mobile/src/views/chat/detail.vue:203` 会用正则 `BASE_API.match(/\/\/([^\/]+)/)[1]`
从中抠主机名拼 WebSocket 地址，相对路径会让它抛 TypeError。

### 4.3 Docker 把 jar 挂载点建成了目录

首次 `docker compose up` 时 `app/app.jar` 还没上传成功，
Docker 对 bind mount 的源路径**不存在时会自动创建成目录**，
于是容器报 `Invalid or corrupt jarfile`。

补传 jar 后**必须重建容器**：

```bash
docker compose rm -sf backend && docker compose up -d --force-recreate backend
```

单纯 `restart` 无效 —— 容器会保留创建时的挂载类型。

### 4.4 大陆机器装 Docker：get.docker.com 被墙

```
curl: (35) Recv failure: Connection reset by peer
```

改用云厂商 apt 镜像（腾讯云机器用内网源，不计流量）：

```bash
curl -fsSL https://mirrors.tencentyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.tencentyun.com/docker-ce/linux/ubuntu noble stable" > /etc/apt/sources.list.d/docker.list
apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

**还要配镜像加速**，否则拉 `mysql:8.0.36` 同样失败：

```json
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com", "https://docker.m.daocloud.io"] }
```

### 4.5 源雀本身的三个上游 bug

| 位置 | 问题 | 处理 |
|---|---|---|
| `configFile/scrm_push.zip` | **建表 SQL 藏在这个 zip 里**，README 只字未提；而 `ddl-auto: none` 不会自动建表 | 解压后导入，52 张表 |
| `frontEnd/pc` 依赖 | `@vitejs/plugin-vue-jsx@3` peer 要 vite 4/5，项目用 vite 6，`npm install` 和 `npm ci` 都 ERESOLVE 失败 | 该插件未被 `vite.config.ts` 引用，用 `--legacy-peer-deps` 绕过 |
| `mobile/src/components/Upload.vue:2` | 死导入不存在的 `getVideoPic`，导致 vite dev 启动报错 | 删除该导入 |
| `mobile/src/config.js` | 硬编码的 dev token 签发于 2026-03-03、7 天过期，本地打开弹「登录状态已过期」 | 写脚本定期刷新 |

### 4.6 必须做的安全加固

| 项 | 上游默认 | 我们的处理 |
|---|---|---|
| **JWT 签名密钥** | `JwtUtils.java:13` 硬编码 `iYqueSecretKeyForJwtTokenGenerationAndValidation`，**公开在 GitHub 上** | 改为读 `IYQUE_JWT_SECRET` 环境变量，生产用 64 字节随机值 |
| 管理员账号 | `iyque` / `iyque.cn`，写在 application.yml | 换自定义账号 + 20 位随机密码 |
| 数据库 | root/root | 独立账号 + 随机密码，只绑 127.0.0.1 |
| SQL 日志 | `show-sql: true` + MyBatis StdOut | 全部关闭 |
| 端口暴露 | — | 18085/13306/16379 **只绑 127.0.0.1**，对外只开 80/443 |

⚠️ **JWT 密钥那条最要紧**：不改的话，任何人都能给你的部署伪造管理员 token 直接登录。
我们改完实测：用上游公开密钥伪造的 token 返回 `401 token失效` ✅

## 七、如果重来一遍

按这个顺序做，能省掉我们走的所有弯路：

1. **先确认企微是「认证」不是「验证」** —— 没认证先去认证，¥300 + 10-15 工作日
2. **第二步就去买域名 + 备案**，别先折腾技术 —— 备案是 8-12 工作日的死时间，
   而且是整件事的唯一瓶颈，越早开始越好
3. 域名选 `.cn` 或 `.com`，境内注册商，**组织实名，持有者 = 企微认证主体的完整名称**
4. 服务器买大陆的，**先测到 `qyapi.weixin.qq.com` 的延迟**再决定
5. 备案等待期间再搭环境、熟悉后台、规划标签体系
6. 备案通过后配证书 + 企微对接，当天就能上线

**最大的教训**：我们花了大半天把系统部署到香港服务器上，全部跑通、安全加固做完，
才发现企微根本不认未备案域名 —— 整套要迁走。
**行政流程的前置条件，要在写第一行配置之前就查清楚。**
